## No grade T for an unreachable server, removable events, dangling CNAMEs and a deeper JS secrets scan

### TLS: not measured is not "certificate not trusted"

A certificate that could not be fetched at all -- DNS down, a timeout, the port closed -- was
graded **T** ("certificate not trusted"). A monitor then raised a HIGH event such as *TLS grade
regressed from A+ to T* for an outage of the scanner's own network, and the scan listed *Poor
TLS grade (T)* and *No modern TLS versions offered* for a server it never reached.

Now a server that gives no TLS connection is reported as *TLS was not measured*, with the reason,
and produces no TLS findings and no grade. Grade T is kept for a certificate that was seen and
failed verification, or has expired.

### Removing wrong monitor events

Events raised in error can now be removed: tick them under **Recent monitor events** and choose
**Delete selected**. They leave the history and the counts; the reports they point to stay. Each
removal is recorded in the audit log (`monitor_event.delete`, with what was removed). Viewers
cannot remove events. API: `POST /api/monitor-events/delete` with `{"ids": [...]}`.

### Is a dangling CNAME really claimable?

Every dangling CNAME to an `azurewebsites.net` name was reported as a possible takeover, and the
DNS lookup page said only that claimability "depends on the provider". Following the providers'
own documentation, a takeover now needs two things: someone else can create the target name
again, and the provider would then serve your name from it.

- **Names only the owner can create** are reported as a stale record to clean up, not a takeover:
  - Azure App Service *secure unique default hostnames* (`<app>-<16-char hash>.<region>-NN.azurewebsites.net`);
  - Azure Front Door Standard/Premium endpoints (`<name>-<hash>.z01.azurefd.net`), which also
    need a `_dnsauth` TXT record or a certificate for a custom domain;
  - public IP labels with a domain name label scope (`<label>.<hash>.<region>.cloudapp.azure.com`);
  - S3 buckets in an account regional namespace (`…-<account id>-<region>-an`);
  - AWS Amplify, API Gateway and App Runner names, whose ids AWS assigns.
- **Azure App Service, classic names** (`<app>.azurewebsites.net`): after deletion the name is
  reserved for the original tenant only for a while. DomainLens now looks up the TXT record
  `asuid.<name>`. When it holds the domain verification ID, App Service binds the name only to
  that subscription, so it is not claimable. When it is missing, a CNAME alone is accepted and the
  takeover finding says so. Only a value shaped like a verification ID counts: a wildcard TXT
  record (such as `v=spf1 -all` for every name in the zone) also answers for `asuid.<name>`.
- Azure Container Instances (`azurecontainer.io`) were added to the services that can be claimed.

The DNS lookup page now gives the same verdict as the scan.

### JavaScript secrets scan

The scan read only the scripts the HTML loads; a Vite or Next.js app keeps most of its code in
chunks. It now also follows the code chunks those scripts name (up to 15 more same-site files)
and reads public source maps, which it reports as a finding of their own.

- More key formats: OpenAI, Anthropic, SendGrid, Mailchimp, Mailgun, GitLab, npm, Shopify,
  Stripe restricted keys, Telegram, Discord and Teams webhooks, Azure Storage connection strings
  and SAS tokens, Mapbox secret tokens.
- A JWT is decoded: a Supabase service_role key is critical, an anon key informational.
- A generic `apiKey: "…"` counts only when its value looks random; the same key in several files
  is one finding.
- The advice says which key (masked) and in which file; the result says what was analysed, and
  that nothing was found only when something could be looked at.
- The results card moved to the **Security Audit** tab, next to the rest of the audit.

### Results where you chose the checks

- The active tests -- weak authentication, the active vulnerability scan and the own
  infrastructure tests -- are shown on the **Security Audit** tab, where they are chosen, under a
  heading of their own that appears only when one of them ran. Weak authentication and the active
  scan were on the Web tab.
- The open relay and open resolver tests have a results card: per mail host and name server,
  whether it relays or recurses, refuses, or could not be measured.
- IPv6 is chosen under *Network & OSINT*, the tab it is shown on.
- On a phone the result tabs are chips that flow in a few rows, instead of one per line filling
  the first screen; the cipher tables become cards instead of scrolling sideways.

### Upgrading

Nothing to do. Events raised in error before this release stay until they are removed.
