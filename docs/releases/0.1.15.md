## Known vulnerable versions: PHP2Shell (CVE-2026-109618, CVE-2026-109619)

PHP2Shell is unauthenticated remote code execution in PHP itself, fixed on 21 October 2026 in
PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35 and exploited the same day. PHP 8.1 and older get no fixes.

### In every scan and monitor

The Security audit compared nothing: "X-Powered-By: PHP/8.2.7" was reported only as a version
leak. The version a server shows (X-Powered-By, or PHP/... in the Server header, redirects
included) is now compared with the release that has the fix:

- **vulnerable** -- older than the fix for its branch, or a branch without fixes: a critical
  finding;
- **has the fix** -- nothing to report;
- **cannot tell** -- PHP in use but its version hidden, or a distribution build
  ("8.2.7-1~deb12u1"), whose package may carry the fix without a new number: an informational
  finding with what to check on the server. Never "clean".

Monitors pick it up on their next scan.

### Across the organisation: Tools → Versions

A new page checks every domain in the portfolio that has a website (or domains you paste),
ten at a time, and lists each with what its server shows and the verdict, worst first. **Which
sites** can be the whole portfolio or one organisation unit (that unit and the units under it).
A domain that sits in no unit stays in the whole-portfolio list only. Each site's home page is
asked for once, like a browser; nothing is sent to trigger the flaw, and a redirect into the
server's own network is not followed. A version that is not shown cannot be judged from outside
-- an agent-based scanner such as InsightVM sees the installed package.
**Export CSV** hands the list to the teams that patch, one row per domain, with every cell
guarded against spreadsheet formulas (the server headers are not ours to trust).

### Your own rules: Admin → Vulnerability rules

The next vulnerable version no longer waits for a release. An administrator adds it as a rule:
the product, the token it shows itself by (`nginx` in `nginx/1.27.1`), where to read it (a
header, or the page's generator tag), the release with the fix per branch, and whether older
branches are vulnerable or came before the flaw. Every scan and the version check use it from
then on. A rule is data, not code: it cannot run anything, send a request or bring its own
regular expression, and a rule the engine cannot use is refused with every reason at once.

**Test** shows what a rule reads from pasted response headers and what it decides, before it is
saved. PHP2Shell is the first built-in rule; it cannot be changed or switched off, but it can be
the start of a rule of your own. Every change is in the audit log.

Rules move between instances as one JSON file: **Export rules** writes your own rules, **Import**
reads such a file -- all of it, or nothing when one rule cannot be used. Four example rules for
serious, exploited flaws come with it (Apache path traversal CVE-2021-41773/CVE-2021-42013,
Apache mod_rewrite CVE-2024-38475, nginx resolver CVE-2021-23017, PHP-FPM CVE-2019-11043). They
are not switched on by themselves: an administrator adds the ones they want. A rule can name the
release a flaw came in with (**Introduced in**); older versions are then not affected.

The engine also reads a distribution named after a version -- `Apache/2.4.52 (Ubuntu)` -- as a
distribution build ("cannot tell"), matches a product name as a word of its own (Tomcat's
`Apache-Coyote` is not Apache), and has a fourth outcome, **not affected**, for a branch
from before the flaw. On Tools → Versions, "No PHP seen" is now "None of the software seen";
in the CSV, `not_seen`.

### Portfolio export of a unit that does not exist

`GET /api/portfolio/csv?unit=…` with a unit that does not exist answered with a file of only
headers, which reads as "this unit has no domains". It is now refused with 404 Unknown unit.
The export from the portfolio page always names an existing unit and is not affected.

### Upgrading

Nothing to do. A script that downloads the portfolio export for a unit by number gets a 404
instead of an empty file when that unit has been removed or merged.
