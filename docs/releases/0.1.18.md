## What happened, as lists to filter

**Monitoring → Domain changes** is a new page next to the domain portfolio: every change of the
portfolio's domains, as a table to filter on what changed (registrar, reseller, name servers,
phase, expiry, DNS answers, decision, threat intel, contact, unit, added, removed), on who found
or made it (a registry lookup, a change by hand, an import), on a unit, a period and any text --
a domain, a registrar's name, a person. Each row shows the value before (struck through) and
after, and for a change by hand or an import the account that made it. **Download CSV** gives
exactly the filtered rows. Before, the portfolio showed the last fifteen registry changes as
sentences at the bottom of the page, and a change by hand was in the audit log only, often
without the domain it was about.

Changes by hand and by import are recorded from this version on. Registry changes recorded
before it are on the page too, with before and after read back from their sentence.

**Monitoring → Monitor events** is a new page next to the monitors: every monitor event, to
filter on kind (changed, scan failed, DNS did not answer, baseline, no change), severity,
monitor, unit, period and text, each filter saying how many it would show. It opens without the
"no change" events; one click shows them too. **What changed?** opens the comparison in the
row, and **Delete selected** removes wrong events as before. The monitors page keeps the five
latest events, with a link to the page.

## A changed DNS record is shown as such

A monitor raised "A record for example.com changed value" when the record it watches changed,
but that record was not part of the comparison, so **What changed?** said nothing moved. The
event now names the values (`changed value: 192.0.2.10 -> 192.0.2.11`), and the comparison has a
row for the watched record with its value before and after -- for older events too, as it is
read from the two scans. A change event whose comparison is known to show nothing (one of the
earlier way of detecting changes) says so in the list.

## The figures on Reports open the domains behind them

On **Reports → Dashboard** every tile, rating, control, risk and area is clickable. "Insufficient
hash for TLS key-exchange signatures (SHA-1) -- 8" now opens the eight domains, each with its
rating, unit, scan date and a link to its report; a control opens every domain with its state
(in place, missing, not measured); an area its domains with their findings. The list opens under
the card that was clicked, **Copy domains** copies the names, and the address keeps the list
open, so a link shows the same. API: `GET /api/reporting/dashboard/drill?kind=finding&value=…&severity=high`
(kinds `finding`, `category`, `control`, `rating`, `severity`, `domains`, `accepted`).

On **Reports → Trends** a day in a chart opens what that chart counts: the issues and the TLS and
header scores of that day's scans, each against the scan of the same domain before it, with
**What changed?**; the scans of the day for scan volume; and the monitor events of the day for
the event chart, which used to open the scan list. The ServiceNow tile lists the events with an
incident, and a domain under **Noisiest domains** filters the page on it. API:
`GET /api/reporting/day?day=YYYY-MM-DD`, and `/api/monitor-events` takes `severity`, `type`,
`q`, `unit`, `from`, `to`, `domain`, `servicenow=1` and `offset`.

## A manual in the app

**Help** (in the header and the footer) is a manual in Dutch: what each page is for and how to use
it, how DomainLens reports (measured, not measured, not applicable), the rating, and what to do
when nothing runs on its own. It has a contents list with a search. The source is
`static/help/handleiding.md`.

### Upgrading

Nothing to do. The change log table gets five columns and two indexes on first start. A script
that reads `GET /api/monitor-events` keeps working: `events` is as it was, with `total`, counts
and filters added. A notification rule or ServiceNow mapping that matches the exact summary
"… changed value" should match its start, as the values now follow it.
