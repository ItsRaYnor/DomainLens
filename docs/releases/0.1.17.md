## A unit's contact can be added, changed and removed later

A unit's contact could only be chosen when the unit was made; to give an existing unit a
contact, it had to be added again. The unit's own page (**Monitoring → Organisation**, click the
unit) now has a **Contact** card. It shows the unit's contact, or the one it inherits and which
unit sets it. With the Analyst role you choose an existing contact, an account or "New
contact…" and **Save contact**; **Remove contact** takes the unit's own contact away, after
which it has the contact of the unit above it again. The contact itself is kept.

Every edit of a unit is now in the audit log with what changed: `portfolio.group_update` has
`changes`, with the contact (and the name, parent, expected registrar or alert addresses)
before and after.

## Importing the portfolio updates the domains already in it

Importing a CSV with a row for a domain already in the portfolio -- for instance the export,
with `threat_intel` switched to `yes` -- reported that domain as "already there". Part of the
row was applied, but nothing said so; the export's own threat intel states (`missing`,
`unmeasured`) and its `mail` column came back as "not understood", and the unit's contact was
copied onto every domain that inherited it.

An import now updates existing domains from the columns the file has -- unit, decision, threat
intelligence and contact -- and afterwards shows:

- how many domains were added, updated and unchanged;
- per domain, each field that changed and what it went from and to;
- every value it could not use, with its column and the reason;
- domains named on more than one line, and the columns it did not read (those DomainLens
  measures itself, such as `phase`, `registrar`, `mail` and `web`).

An empty cell or a missing column never clears a stored value. An exported file imported
again unchanged changes nothing. The `portfolio.import` audit entry lists the changes.

### Upgrading

Nothing to do. One behaviour changed: the unit chosen under the import no longer moves a domain
that is already in another unit when its line names no unit. New domains, and domains not in a
unit yet, still go there; to move a domain, name the unit on its line. The result lists the
domains that stayed where they were. `POST /api/portfolio/import` answers with the new fields
`updated`, `changes`, `not_used`, `stayed`, `repeated` and `columns`. Its `unchanged` now lists
only the existing domains the import did not change; a script that read it as "already in the
portfolio" should add `updated` to it.
