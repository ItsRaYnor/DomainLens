## A redirect to another domain is that domain's measurement

A site that redirected to another domain was judged on the other domain's server. When
`example.org` (its own server: `Apache`, no PHP shown) sent its visitors to `example.net`
(`nginx`, `X-Powered-By: PHP/8.3.36`), Tools → Versions reported `example.org` as "Has the fix
PHP/8.3.36" with server "Apache nginx", and the Security audit reported that PHP version as
`example.org`'s own version and version leak. It was neither: the version of another server says
nothing about this one, and a vulnerable one there is not fixed on this domain's server.

Now every answer on the way is read on its own. Only the answers on the domain's own registered
name (http to https, `www.`, a subdomain) are its measurement, the redirect itself included -- a
redirect can still show the domain's own version. What the server at the end of a redirect to
another domain shows is kept apart and named as that domain's:

- **Tools → Versions** shows the domain's own result, and under it **Redirects to example.net**
  with that server's headers and verdict; each of its reasons reads "On example.net:". The table
  is still sorted by the domain's own result.
- **Export CSV** has a new second column, `measured_on`: the domain itself, or, in the rows after
  it, the other domain it redirects to -- the server to patch.
- **Security audit**: the disclosed headers, version leaks and known-vulnerability verdicts are
  those of the domain's own server. The report shows the other server's headers apart. A
  vulnerable version there is a finding of its own, naming that domain ("example.net, where this
  domain redirects, shows a vulnerable PHP version"), with the fix for whoever runs it. A version
  that server hides is left to its own scan rather than reported here as "cannot tell".

## A domain without a website no longer vanishes from Tools → Versions

A domain was dropped before the check when it did not resolve to a public address, and the page
then showed nothing for it -- not even a row. A domain whose DNS has no address now gets its own
result, **No website in DNS**, and one that points inside a network gets **Not checked**. A DNS
lookup that gives no answer is **No response**: it says nothing about the site. When only `www.`
has an address, `www.` is checked. In the CSV these are `no_address`, `not_checked` and
`no_response`. Every host is looked up before it is asked for, `www.` included.

Every row now has **Details** to fold open: what DNS said per host (`example.org`, `www.`), each
address asked for and whether it answered, and every step of the redirects -- status, Server,
X-Powered-By, and whether it counts for this domain or the other one. A result can be followed by
hand without a terminal.

A domain pasted with a slash in front (`/example.org`, `//example.org`) was read as an empty
name ("No domains to check"); it is now read as `example.org`.

### Upgrading

Nothing to do. Monitors of a site that redirects to another domain can show changed findings on
their next scan: the other server's version leak and PHP2Shell verdict move to the new redirect
finding, or drop out when that server is fixed or hides its version. A script that reads the
versions CSV by column position, rather than by header name, has to skip the new `measured_on`
column.
