## OSINT: within the free API limits, and "not measured" in plain words when not reached

When the server's own DNS hiccuped during a scan, every OSINT source showed the raw exception
(`HTTPSConnectionPool(host='web.archive.org', port=443): Max retries exceeded … NameResolutionError …`),
while the summary above said **Threat feed hits: 0** in green, **Wayback snapshots: 0** and
**Related hostnames: 0** -- feeds that were never reached, shown as a clean result.

- A failed lookup now says what happened and to which source, e.g. *This server could not look up
  web.archive.org: its DNS did not answer. Not measured; try again later.* Timeouts, refused
  connections, TLS failures and HTTP errors (such as the Internet Archive's 503) get their own
  short wording. The same wording is used by the other checks that call out to the internet.
- A resolver that does not answer is asked once more a second later before a source is given up.
- The OSINT summary shows **Not measured** for counts whose source was not reached; the *OSINT
  Clean* tile says *Not tested* instead of *Pass*; VirusTotal says *Not measured* when its key is
  set but the lookup failed, rather than *not configured*.
- When several sources fail on DNS at once, the summary says that this server's DNS did not answer
  and to scan again later.
- A monitor no longer reads a scan whose threat feeds were all unreachable as the domain dropping
  out of the feeds.

### Free API tiers are kept to

The free VirusTotal key allows 4 lookups a minute and 500 a day, ip-api.com 45 a minute. A few
scans close together went past that; the answer (HTTP 429) was shown as an error or as nothing,
and every following request failed too while still counting against the quota.

- Each service has a budget under **Settings → Integrations → API limits**, with the free tiers as
  default; raise it for a paid key. A lookup waits up to 20 seconds for a free slot, then is
  reported as *not measured* with the reason, rather than sent anyway. The mail analysis's
  VirusTotal link lookups share the same budget.
- A service that answers 429 is left alone for as long as it asks (`Retry-After`), or a minute.
- An OSINT result in which a source failed for a passing reason (DNS, a timeout, a rate limit) is
  no longer cached for a day: the next scan asks again instead of replaying the failure.

### Upgrading

Nothing to do. The new settings start at the free-tier limits.
