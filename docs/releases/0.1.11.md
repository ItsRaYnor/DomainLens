## IP data from the most reliable sources, your own address, and a portfolio that fits

### Where IP data comes from

The network and the location of an address both came from ip-api.com's free endpoint: plain
HTTP, for non-commercial use only, with every address sent to it. And two SORBS blocklists that
no longer exist answered "not listed" for everything.

- **Network** (ASN, holder, prefix, country of registration) now comes from RIPEstat over HTTPS,
  with Team Cymru's IP-to-ASN service over DNS when RIPEstat cannot be reached. Free, no key.
- **Location** comes from MaxMind GeoLite2, downloaded to this server and read here: no address
  leaves it. Without a MaxMind account it says *not configured*; a database more than 30 days
  out of date is not used (the GeoLite licence). The MaxMind credit is shown with every location.
- **ip-api.com is off** by default. Its hosting and proxy flags read *not measured* until it is
  switched on under Settings → Integrations → IP context.
- **SORBS is removed** from the DNS blocklists. Every list is first asked for its own test
  address; a list that does not answer it, times out or returns an error code is *not checked*
  for that address instead of clean. When no list could be asked, the blacklist tile says
  *Not tested*, not *Pass*.
- **The Spamhaus PBL is no longer a listing.** A home or office address answered by ZEN with a
  PBL code only showed *Listed on 1 blocklist(s)* in red, and a monitor would have raised a
  critical event. It now reads *end-user range (PBL)*, with what that means; an SBL or XBL code
  beside it still makes it a listing. The mail analysis gives a medium finding when a message
  was sent straight from such an address. A monitor whose last scan counted only the PBL may
  report the blacklist listing as resolved once.

### Your own public address

Tools → IP address has a **My IP address** button. It looks up the address your browser
connects from. From a private address (on the server's own network, or behind a proxy that is
not trusted) it shows the server's public address instead, and says that this is the server's.
The server's address comes from RIPEstat (RIPE NCC, in the EU) over HTTPS.

### DNS lookups start in the EU

Tools → DNS record offers DNS4EU, the EU's public resolver, in all five variants (unfiltered,
protective, child, noads, child-noads), each resolver labelled with where it is run (EU, US,
CH). A lookup now starts on `dns4eu-unfiltered`; before, the list was sorted and started on
`authoritative`. Propagation compares DNS4EU with Cloudflare, Google, Quad9 and the zone's own
nameservers; the filtered variants are not ticked, since their block of a name would read as a
rollout that has not finished. `GET /api/dns/query` without a resolver still uses the system
resolver.

The resolvers are grouped by where they run -- DNS4EU, outside the EU, direct (the zone's own
nameservers and this server) and your own -- each a chip with a plain name and an explanation
on hover; on a phone each group's name sits above its chips. The lookup list has the same
groups.

### Domain portfolio fits its card

The contact column, and the picker that **Link contact** opens, ran past the card: the contact
and the row menu were cut off, more so in a unit below another. The decision and the contact now
share one column (*Decision · contact*), and the picker takes the column's width. On a phone
every row is still a card.

### Upgrading

- New dependency `maxminddb` (in the image).
- For location: create a free MaxMind account and set the account ID and a license key under
  **Settings → API keys**. Without them everything else works and location says *not configured*.
- If you relied on ip-api.com's hosting and proxy flags, switch it back on under
  **Settings → Integrations → IP context**.
- Behind a reverse proxy, set `DOMAINLENS_TRUSTED_PROXY_HOPS` (as before) so **My IP address**
  sees the reader's address rather than the proxy's.
